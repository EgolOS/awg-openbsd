# R7 installer lock and commit durability — w1-n1-v2

## Required invariants

1. **Read-only refusal:** a process that never acquires the lock must not write, rename, chmod, or unlink the lock or any generation; paths, nanosecond mtimes, and inode snapshots must remain identical.
2. **Single holder:** fresh acquisition, dead-owner reclamation, delayed reclamation versus a new arrival, a stopped/resumed initializer, and an eight-way race must admit only one live holder. C and D must never both be admitted alive.
3. **Crash recovery:** killing the initializer after generation mkdir, token-temp write, token rename, immediately before publication, or immediately after publication must not reserve an unrecoverable shared slot. Each boundary gets two retries. A stopped published owner must not be reclaimed.
4. **Commit durability:** every catchable nonzero exit after publication and before the commit record is durable must attempt verified rollback. Successful rollback and failed rollback must have different messages and exit statuses.

## Why this protocol differs from the proposed rename protocol

Destructive compare/rename was the source of the ABA failure. R7 does not rename or remove an observed owner at all:

- A complete token includes generation, PID, a locale/TZ-normalized process start identity, a 128-bit random nonce, and an R7 format tag.
- Private preparation uses a fresh `mktemp` directory under the run's WORK, writes `owner.tmp`, then renames it to `owner`. It does not reserve a shared generation.
- One exclusive `ln -s` publishes the **complete token in the link itself**. A missing root is the first slot; subsequent claims use immutable successor slots. The successful symlink creation is the acquisition linearization point. No `flock`, helper lock, age timeout, sleep-based stale decision, or public CAS rename is used.
- Every predecessor has exactly one successor slot. Slots and release markers are append-only and are **never reused**. A delayed contender can only lose at the old slot; it cannot overwrite the current holder, even if several later holders have already run.
- Only an owner publishes its matching release-token marker. Verification and rollback happen before release. The release marker is the last lock-state mutation by that run.
- A loser exits without shared cleanup. `EEXIST` is a named publication-in-progress refusal, not permission to delete or overwrite anything.
- A stopped owner remains live. A failed `ps`/`kill` check alone is not proof of death: reclamation requires a successful full process table with the PID absent, or a comparable R7 start-time mismatch. Legacy timestamps were not normalized, so a legacy mismatch with a live PID is conservatively refused.

The numeric successor pathname is not a replaceable identity: it is an immutable slot containing a unique full owner token. This deliberately replaces nonce-named public directories and token-checked destructive reclamation. There is no orphan public initialization slot to reclaim in the first four windows. Legacy abandoned `gen-N` directories and pending CAS names are not used as R7 contention slots and cannot wedge R7 publication.

### Limits that must not be hidden

- History grows by one claim and one release marker per normal run; traversal is linear in retained history. There is no live garbage collection. Reset/rotation requires an operator-controlled offline maintenance window with all installer versions stopped and disabled. Do not remove history while a delayed contender could resume.
- Mixing old destructive installers with R7 is not a supported upgrade mode. Quiesce old versions first. A legacy root that has no identifiable owner is refused with its exact path and an offline-repair instruction; guessing that an unidentified initializer is dead would make SIGSTOP unsafe. This is an explicit fail-closed compatibility limitation, not a time-based automatic break-lock.
- The namespace must be trusted and not writable by non-cooperating users. Root can deliberately bypass any advisory lock. Protected work must not be detached into background writers that outlive the owning installer.
- SIGKILL during a file-publication transaction and machine/power loss cannot execute a shell rollback trap. The SIGKILL coverage here is specifically the five requested lock-initialization boundaries. No power-cut recovery/journal claim is made.
- Native OpenBSD execution is NOT RUN (the task prohibits VMs/SSH). Host tests exercise the actual shell functions and real GNU exclusive symlink operation; the full-script BSD shim translates OpenBSD `ln -h` to GNU `ln -T`. OpenBSD's `-h` does not protect against a real destination directory, so publication rejects directories and verifies the resulting token link; cooperative R7 writers never create public directory slots.

### Commit durability implementation

A fixed dependency-free C helper is compiled with base `cc` in private WORK **before publication**. Unlike `sync(8)`, it checks `open`, `fsync`, and `close`. The recorder hashes/stats required members without substituting `unknown`, fsyncs the temporary manifest, renames it, fsyncs installed files and their parent directories, then fsyncs the manifest and its parent directory. Only then is `PUBLISH_STARTED` cleared.

`publish_pair` catches recorder `die`, `exit`, and ordinary errors in a subshell. The EXIT recovery guard also covers unexpected exits and kernel-only/tools-only publication. Rollback validates and compares the restored members, restores the saved precommit manifest (including the case where record rename succeeded but directory fsync failed), and flushes recovery files/directories. Exit **20** means verified rollback; **21** means recovery failed and manual action is required. The lock is retained through verification/recovery.

### Existing-test changes were representation corrections, not weakened gates

The old tests asserted that a refused run changed a symlink-to-directory into a regular file; that is directly contrary to invariant 1. They also required deletion of previous generation directories and a specific rename source-code string — properties of the defective recycling protocol. These were replaced with immutable-token/release-marker assertions and a real complete-token publication test. All original refusal, usage, root-check, signal, PID-reuse, dead-owner, three-way and eight-way behavioral cases remain.

The `ps` shim now forwards unmodeled PIDs to real `ps`; otherwise it claimed even the actual initializer did not exist. The BSD `ln` flag is translated without fabricating success or replacing the link primitive. Harness WORK is private and BSD stat semantics are supplied by default; failed metadata reads no longer silently become successful `unknown` commit records. The existing independent host suite is not skipped or relaxed.
