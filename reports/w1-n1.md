## What the lock is now

Canonical lock is a **single regular file** carrying the owner token
(`gen=N pid=P start=S nonce=X`). Design, kept from the crashed worker's
CAS-slot direction and repaired:

1. **Generation directory** `gen-N` holds the owner record; N is bumped on
   every reclaim.
2. **CAS slot** `lock.cas.N` — a symlink to `gen-N`, created with
   `ln -s` (O_EXCL semantics). The first creator wins; losers get EEXIST.
3. **Atomic publish** — the canonical `lock` name is switched onto the
   freshly created slot with a single rename (`mv -T` on GNU, plain `mv`
   on OpenBSD — flag selected at runtime by `lock_mv_t`), so the canonical
   name is never transiently absent (guarantee 5).
4. **Stale reclaim** compares pid **and recorded start time**
   (`ps -o lstart=` / `ps -o start=`), so a recycled pid is not mistaken
   for the original owner (guarantee 3).
5. **Refused contenders** read the lock and exit without touching it —
   verified on the usage-error and root-check exit paths (guarantee 2).

Fixes applied over `abddf0e`: the CAS slot creation path used `mkdir`
where the slot must be an `ln -s` symlink (the test shims expose `ln`,
not `mkdir`, for the slot); the `mv -T` probe helper (`lock_mv_t`) was
returning empty under the shim PATH, so the probe now falls back to plain
`mv`; the re-check after claiming reads the slot target instead of the
canonical name, closing the two-winner window in the 8-way race.
